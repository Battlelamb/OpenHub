## 2. Technical Analysis for Social Platforms

### **Supabase: The All-in-One Powerhouse**
Supabase is the strongest choice for avoiding "microservice sprawl."
- **Pros:** Built-in Auth (50k MAU) and Storage (1GB) mean you don't need external providers.
- **Cons:** The 7-day inactivity pause is a nuisance for low-traffic projects.
- **Optimization Strategy:** Set up a GitHub Action to "ping" the database weekly with a `SELECT 1` to prevent pausing.

### **Neon: The Postgres Purist**
Neon is best for developers who want a standard Postgres experience with high performance.
- **Pros:** Scale-to-zero compute (up to 100 CU-hours) and instant branching for testing.
- **Cons:** No built-in Auth or File Storage; requires integration with services like Clerk.
- **Optimization Strategy:** Use connection pooling (PgBouncer) to stay within compute limits for high-request apps.

### **Convex: The Realtime Specialist**
Convex provides a "reactive" engine where every query is a subscription.
- **Pros:** Infinite real-time updates without WebSockets/polling code.
- **Cons:** Vendor lock-in and a strict **10,000 row per table** limit on the free tier.
- **Optimization Strategy:** Implement aggressive TTL (Time-To-Live) scripts to delete or archive old tweets to stay under row limits.

## 3. Optimization Roadmap (Free Tier $0/mo)

To run a high-traffic app entirely on free tiers (e.g., Netlify + Chosen Backend), follow these strategies:

### **CDN & Caching**
- **Stale-While-Revalidate (SWR):** Implement `Cache-Control: s-maxage=60, stale-while-revalidate=3600` on the edge to reduce database reads.
- **Netlify Edge Functions:** Offload auth checks and geo-filtering to the edge (1M free calls) to save standard function invocations.

### **Media & Images (The Bandwidth Killer)**
- **Cloudinary Free Tier:** Use Cloudinary for image hosting. Its `f_auto` and `q_auto` features reduce image weight by ~80%.
- **Netlify Image CDN:** Use built-in resizing (`?nf_resize=fit&w=500`) to avoid serving full-resolution 5MB photos to mobile users.

### **Database Efficiency**
- **Denormalization:** Store `like_count` directly on the `Tweet` record instead of calculating it via `COUNT(*)` from a separate table.
- **Keyset Pagination:** Use `WHERE created_at < last_timestamp` instead of `OFFSET` to maintain performance as data grows.

### **Bundle Size Optimization**
- **Tree-Shaking:** Import only specific icons and components.
- **Lazy Loading:** Use `React.lazy()` for non-critical pages like Settings or Profile to keep the initial Home Feed load under 100KB (Gzipped).
