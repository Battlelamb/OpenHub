## Executive Summary

Build a production-ready React + Vite + TypeScript + Tailwind v4 + shadcn/ui dashboard that serves multi-agent coordination UI at `/dashboard`. 16 requirements (UI-01..UI-16) across 5 waves, 7 plans total.

### Objectives
- Centralized query-key factory (`qk` namespace)
- Typed entity shapes (Agent, Task, Workflow, DlqItem, etc.)
- TanStack Query hooks for all resources
- `useWebSocketSync` hook with hybrid merge/invalidate strategy
- First-frame JWT auth for WS (Phase 2 D-03 compliance)

### Key Files
- `web/src/lib/query-keys.ts` — qk factory for agents/tasks/workflows/health/dlq/costs/memory/locks
- `web/src/types/entities.ts` — typed shapes
- `web/src/hooks/queries/use*.ts` — 9 query hooks
- `web/src/hooks/useWebSocketSync.ts` — WS lifecycle with exponential backoff
- `web/src/hooks/useWebSocketSync.test.ts` — verifies NO `?token=` in WS URL

### Sync Strategy (D-05/D-06)
| Event Type | Examples | Action |
|------------|----------|--------|
| Critical | agent_status_changed, task_status_changed, task_progress | `setQueryData` optimistic merge |
| Non-critical | heartbeat, metadata_changed | `invalidateQueries` background refetch |
| Special | token_expiring, error, connected | Toast + invalidate all on reconnect |

### Acceptance Criteria
- [ ] qk factory exports keyed functions for all resources
- [ ] useWebSocketSync owns single WebSocket to /v1/ws/ui
- [ ] WS sends first-frame JWT auth (NO token in URL)
- [ ] WS events dispatch correctly (merge vs invalidate)
- [ ] Exponential backoff with jitter, max 30s
- [ ] AppShell mounts useWebSocketSync once
- [ ] useHealth polls /v1/health every 10s for topbar dot

### Pitfalls
- **WS URL token** — grep test must prove `?token=` NEVER appears
- **Shared file races** — i18n/index.ts and msw/handlers.ts are FROZEN after this plan
