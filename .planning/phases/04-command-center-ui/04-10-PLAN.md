<objective>
Close the backend/frontend endpoint mismatch documented in 04-UAT.md "Major Gap Discovered". Five frontend hooks (useAgents, useTasks list, useCosts, useMemoryEntries, useLocks) call paths the backend does not expose. Three more (useWorkflows, useDlq, useCreateTask) only "work" because of FastAPI's 307 redirect on missing trailing slash, which is fragile and adds latency. Beyond URLs, the auth surfaces are also misaligned: /v1/dlq/ requires X-Admin-Key, /v1/costs/summary + /v1/memory/keys + /v1/locks/* require X-API-Key, but the dashboard sends JWT Bearer only. And critically, /v1/locks/ has NO list endpoint (only single-resource /status check) and /v1/workflows/ has NO list endpoint (only POST, /admin/all, and /{id}). msw handlers in web/src/mocks/handlers/ mock the fictitious paths, so unit tests pass against a lie - this is what hid the gap.

This plan is doing three things at once because they are inseparable for a real fix:

1. **Backend additions (locked decisions, no executor latitude):**
   - Add `GET /v1/locks/` returning a list of currently held resource_locks (active = released_at IS NULL AND expires_at > now). New endpoint, JWT auth.
   - Add `GET /v1/workflows/` returning the in-memory running workflows list (delegates to existing hatchet_service._running_workflows the same way `/admin/all` does, but JWT auth without admin requirement).
   - Switch `/v1/costs/summary`, `/v1/memory/keys`, `/v1/locks/status`, and the new `/v1/locks/`, `/v1/workflows/` endpoints from ApiKeyAuth to `CurrentAgent` (JWT). This is consistent with `routes_tasks.py` `get_task` line 121 - the dashboard's read-only entry points should accept JWT, not X-API-Key.
   - Switch `/v1/dlq/` admin dep to accept either JWT admin (CurrentAdmin) OR X-Admin-Key (backward compat for existing CLI workflows).

2. **Frontend hook rewrites (one per area):**
   - Each hook fetches the REAL backend path and adapts the REAL backend envelope to the typed shape consumers (`agents/index.tsx`, `tasks/index.tsx`, `costs.tsx`, `memory.tsx`, `locks.tsx`, `workflows/index.tsx`, `dlq.tsx`) already expect. No consumer code needs to change because the adapter normalizes shapes inside the hook.
   - `useCreateTask` and `useCancelTask` keep working but use trailing slash explicitly so they never trigger the 307 redirect.

3. **msw handler realignment + entity type updates:**
   - Each msw handler now mocks the REAL backend path with the REAL backend envelope. If unit tests previously passed because both the hook and the mock used a fictional path, they now pass because both use the real path with the real shape.
   - `web/src/types/entities.ts` is updated to match what the adapters produce so consumer routes compile.

**Why one plan, not five:** the msw handler and the hook for a given area must move together (otherwise tests pass against fiction); the backend route additions and the hook rewrite for that area must move together (otherwise the new path 404s). Splitting by area would create ordering footguns. Five tasks within one plan, each focused on one area (agents, tasks-list, costs, memory, locks, workflows, dlq+trailing-slash), keeps the change auditable while respecting the "all or nothing per area" coupling.

**Decisions locked here, NOT deferred to executor:**
- **Pagination on /v1/tasks/search**: Hardcode `page=1&limit=100` in `useTasks` for now. Real pagination is a Phase 5 polish item. The current consumer `tasks/index.tsx` does not have a pager UI and the task list is small enough that 100 covers all live data. This is documented in the hook with a TODO comment.
- **Empty arrays vs undefined**: Hooks return `Type[]` (default `[]` on failure paths is the consumer's job). Adapters always return arrays - never undefined - so `tasks?.length` checks remain truthy.
- **agent_name -> name mapping**: Backend Agent uses `agent_name` (see `app/models/agents.py:162`), discovery_service.py emits `agent_name` (line 22). UI uses `name`. Adapter renames in the hook so consumers stay simple.
- **Task field mapping**: Backend TaskResponse uses `assigned_agent_id`, `last_error`; UI Task uses `agent_id`, `error`. Adapter renames.
- **Locks list endpoint shape**: `[{resource_id, agent_id, acquired_at, expires_at, conflict?}]` matching `web/src/types/entities.ts` ResourceLock. Backend SQL pulls from `resource_locks WHERE released_at IS NULL`.
- **Workflows list endpoint shape**: returns `[WorkflowResponse]` (existing model with `run_id`, `name`, `status`, etc.). The hook adapter maps `run_id -> id` to match UI's Workflow type.
- **DLQ adapter**: Backend returns `{dead_letters: [{task_id, title, retry_count, last_error, created_at, ...}]}`. UI DlqItem expects `{task_id, title, retries, error, failed_at}`. Adapter renames.
- **Memory keys envelope**: Backend `/v1/memory/keys` returns `{keys: [{key, value_type, tags, created_by, updated_at}], total}`. UI MemoryItem expects `{key, size_bytes, age_seconds, value_preview?}`. Backend doesn't expose size_bytes or age. Adapter computes age_seconds from `updated_at` (now - updated_at), sets size_bytes to 0 (we don't have value length without reading), value_preview to undefined. We update the UI MemoryItem type to make size_bytes optional since the backend cannot reliably surface it from /keys without N+1 reads.

```python
@lock_router.get("/")
async def list_active_locks(
    current_agent: CurrentAgent = None,
    database: Database = Depends(get_database),
) -> List[Dict[str, Any]]:
    """
    List currently held resource locks (active = not released yet).
    Used by the Phase 4 dashboard locks panel (UI-14). JWT auth.

    Returns ResourceLock[] matching web/src/types/entities.ts:
    [{resource_id, agent_id, acquired_at, expires_at, conflict}]
    """
    rows = database.fetch_all(
        "SELECT id, resource, locked_by, created_at, expires_at "
        "FROM resource_locks WHERE released_at IS NULL "
        "ORDER BY created_at DESC LIMIT 100"
    )
    locks: List[Dict[str, Any]] = []
    now = datetime.now(timezone.utc)
    for r in rows:
        r = dict(r) if not isinstance(r, dict) else r
        # An expired-but-not-released lock is a "conflict" (stale lock detection)
        conflict = False
        exp = r.get("expires_at")
        if exp:
            try:
                exp_dt = datetime.fromisoformat(str(exp).replace("Z", "").replace("+00:00", ""))
                if now > exp_dt:
                    conflict = True
            except (ValueError, TypeError):
                conflict = False
        locks.append({
            "resource_id": r.get("resource") or "",
            "agent_id": r.get("locked_by") or "",
            "acquired_at": r.get("created_at") or "",
            "expires_at": r.get("expires_at") or "",
            "conflict": conflict,
        })
    return locks
```

```python
async def _dashboard_or_admin_key(

    x_admin_key: Optional[str] = Header(None, alias="X-Admin-Key"),
) -> bool:
    """
    DLQ routes accept EITHER an X-Admin-Key (legacy CLI flow) OR a JWT admin
    Authorization header (dashboard flow). Either is sufficient. This is the
    minimum change that lets the React dashboard hit /v1/dlq/ without storing
    a permanent admin key in the browser.

    s = get_settings()

        return True

    # Try JWT admin

    if not auth_header or not auth_header.lower().startswith("bearer "):
        raise HTTPException(status_code=401, detail="JWT admin or X-Admin-Key required")

        if payload.get("role") != "admin":

        return True
```

```typescript
      age_seconds = Math.max(0, Math.floor((nowMs - updatedMs) / 1000))
```

```python
from fastapi.testclient import TestClient

    body = r.json()

        assert k in body, f"missing {k} in {body}"
    assert isinstance(body["tasks"], list)
```
