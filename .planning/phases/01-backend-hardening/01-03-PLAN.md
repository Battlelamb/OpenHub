**Priority: app/database/repositories/base.py**

Find the `_get_timestamp()` method (around line 59). Change:
```python
def _get_timestamp(self) -> datetime:
    return datetime.utcnow()
```
To:
```python
def _get_timestamp(self) -> datetime:
    return datetime.now(timezone.utc)
```
This single change propagates to all 16 repository subclasses that call `self._get_timestamp()`.

**Additionally in base.py:** When reading a datetime value from a SQLite row in `_row_to_model()`, make it timezone-aware to prevent naive/aware comparison crashes:
- If `_row_to_model` does datetime conversions like `datetime.fromisoformat(row['created_at'])`, add `.replace(tzinfo=timezone.utc)` to the result.
- If it does not do datetime parsing (just passes raw strings), leave it - the comparison fix is in the service layer.

**In app/services/task_service.py:**
Replace all `datetime.utcnow()` with `datetime.now(timezone.utc)`. Also check for `datetime.fromisoformat(...)` calls used in lease comparisons - if comparing against `datetime.now(timezone.utc)`, ensure the parsed datetime is also made aware:
```python
# Pattern that breaks when mixing naive and aware:
lease_until = datetime.fromisoformat(row['lease_until'])  # naive
now = datetime.now(timezone.utc)  # aware
if lease_until < now:  # TypeError!

# Fix:
lease_until = datetime.fromisoformat(row['lease_until']).replace(tzinfo=timezone.utc)
```

**In app/services/agent_service.py:**
Same treatment - replace all `datetime.utcnow()` and fix any fromisoformat() comparisons.

**In app/api/routes_health.py:**
